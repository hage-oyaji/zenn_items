## 2026年3月31日：ソースマップ流出

v2.1.88 が **59.8MB の source map を同梱して出荷された**。

中身は 512,000行の TypeScript。

そこから読み取られたものが、そのままハーネス設計の教科書になってしまった。

```text
32個   コンパイル時フィーチャーフラグ
22個+  GrowthBook のランタイムゲート
44個   未リリース機能
```

見つかった未公開機能のうち、最も話題になったのが **Swarms** である。

共有タスクボードを介して複数エージェントが並列に動き、互いにメッセージを送り合う。

環境変数でプラン別のエージェント台数まで決められていた(Max/Team は3、Free は1)。

出典: [Inside Claude Code's leaked source (The New Stack)](https://thenewstack.io/claude-code-source-leak/)

流出そのものは事故だが、**マルチエージェントの実装が「タスクボード + メッセージング」だったこと**が公になった意味は大きい。

グラフでも DAG でもなかった。

## 2026年4月23日：品質劣化のポストモーテム

2月〜4月にかけて「Claude Code が馬鹿になった」という声が続いた。

Anthropic は4月23日に原因を3つ公表している。

| # | 期間 | 原因 | 影響 |
|---|---|---|---|
| 1 | 3/4〜4/7 | reasoning effort の既定値を high から medium に変更(UIフリーズ対策) | 知性の低下として体感された |
| 2 | 3/26〜4/10 | 1時間以上アイドルのセッションから古い思考を消すキャッシュ最適化がバグり、**毎ターン思考履歴を捨てていた** | 忘れっぽく、同じことを繰り返す。使用量の消費も加速 |
| 3 | 4/16〜4/20 | 冗長さ対策で「ツール呼び出し間のテキストは25語以内」を system prompt に追加 | **Opus 系で知性が3%低下** |

出典: [An update on recent Claude Code quality reports](https://www.anthropic.com/engineering/april-23-postmortem)

3番目が重要だ。

**system prompt に1行足しただけで、コーディング性能が3%落ちた。**

モデルは同じである。落ちたのはハーネスだ。

私はこれを、2026年で最もわかりやすい「ハーネスが性能を決める」の実例だと思っている。

## 2026年7月12日：33,000トークン問題

プロンプトを読む前に消費されるトークン量を、プロキシで実測した記事が 706pt を集めた。

そして最後にこう書かれている。

> **両者とも全タスクを正しく完了した。**

つまり品質差ではない。アーキテクチャ差である。

出典: [Claude Code vs OpenCode token overhead](https://systima.ai/blog/claude-code-vs-opencode-token-overhead)

## 2026年7月25日：80%削っても性能が落ちなかった

同じ問題に、Anthropic 自身が別方向から答えを出している。

Claude Opus 5 / Fable 5 世代に向けて、**Claude Code の system prompt の80%以上を削除した**。

そして、コーディング評価に**測定可能な劣化はなかった**。

推奨も変わっている。

| 旧世代 | Claude 5世代 |
|---|---|
| 明示的なルールを与える | 判断をモデルに委ねる |
| ツールの使用例を書く | **ツールのインタフェース自体を良くする** |
| 情報を前倒しで全部入れる | Progressive Disclosure |
| 指示を繰り返す | ツール説明はシンプルに |
| CLAUDE.md に手動で記憶を書く | 自動保存 |

CLAUDE.md についても具体的だ。

> CLAUDE.md は軽くしておき、**トークンの大半はコードベース内の落とし穴に使え。**

出典: [The new rules of context engineering for Claude 5 generation models](https://claude.com/blog/the-new-rules-of-context-engineering-for-claude-5-generation-models)

## Codex は「ハーネス」という言葉を持ち込んだ側である

2026年のハーネス論において、OpenAI の貢献は製品よりも**語彙**だった。

2026年6月5日、OpenAI は「Harness engineering: leveraging Codex in an agent-first world」を公開する。

内容は、社内で**5ヶ月・約100万行のプロダクトを、人手ゼロ行で出荷した**という報告だ。

そこで示された定義が鋭い。

> **Context engineering は「エージェントに何を見せるか」を問う。**
> **Harness engineering は「システムが何を防ぎ、何を測り、何を正すか」を問う。**

これは2026年で最も引用された区別だと思う。

Context Engineering はモデルへの入力の話だった。

Harness Engineering は**入力・実行・検証・境界の全部**の話になった。

出典: [Harness engineering(OpenAI)](https://openai.com/index/harness-engineering/) / HN 297pt

## これはコーディングエージェントではない

ここが重要だ。

TOP10 のうち 1・2・4・5・9位はすべて**コードを書かせる**ハーネスである。

OpenClaw だけが違う。

```text
常駐する
メッセージングアプリを UI にする
個人のデバイスで動く
メール処理 / 予約 / チェックイン を代行する
```

つまり**生活の常駐エージェント**だ。

「OpenClaw is what Apple intelligence should have been」(2026-02-05 / 518pt)というタイトルが、受け止められ方をよく表している。

2026年8月30日の 2.0 では、933人(うち初参加569人)、16,000件超の PR という規模になった。

- ブラウザアプリが第一の入口に
- クラウド共有セッションによるマルチプレイヤー
- インストールの簡素化(既存サブスクとローカルモデルを利用)

```text
                 │ クラウド/    │
                 │ ローカル(10位)│
                 └──────┬──────┘
                        ▼
                    検証(12位)
                 evals / レビュー
                        │
                        ▼
                 セキュリティ(13位)
              資格情報 / 供給網 / 権限
```

**インプレッション順は、この図の上から下へ、ほぼきれいに並んでいる。**

上流(製品)ほど話題になり、下流(検証・セキュリティ)ほど話題にならない。

そして事故は、下流で起きている。

# 用途別：2026年9月に私が選ぶ組み合わせ

単体では実務にならないので、スタックで書く。

| 作るもの | 推奨スタック | 理由 |
|---|---|---|
| **社内の日常開発** | Claude Code + Skills + AGENTS.md + git worktree | 実績が最も厚い。CLAUDE.md は軽く、落とし穴だけ書く |
| **自社製品にエージェントを組み込む** | Codex の app-server(Apache-2.0)+ 自前の承認フロー | ハーネスだけを OSS で調達できる、現時点で最も現実的な選択肢 |
| **閉域・オンプレ案件** | OSSハーネス(Pi / OpenCode / DeepSeek Harness)+ llama.cpp or vLLM | 外部規約の変更で止まらない |
| **モデルを固定したくない** | OSSハーネス + LLMゲートウェイ | ただしゲートウェイは供給網攻撃の的になった実績あり |
| **社内ナレッジをエージェントに渡す** | AGENTS.md に索引を置き、詳細を Skills に分割 | Vercel の評価では索引常駐が 100%、Skills 既定は 53% |
| **長時間・非対話のタスク** | Codex(非対話実行)+ サンドボックス + 予算上限 | 8時間走るエージェントの暴走は、1分のそれと被害が違う |
| **常駐の個人アシスタント** | 業務環境では非推奨 | OpenClaw 系は権限設計が未成熟 |

そして、どの構成でも共通して必要なものが3つある。

```text
1. トークン会計(cached / cache_write / cost per task)
2. 検証(テスト・レビュー・マージ率)
3. 資格情報の分離(エージェントに直接持たせない)
```

これは12ヶ月分の事故が教えてくれたことだ。

# 2027年に向けた3つの見立て

### 1. ハーネスは「買う」から「組む」へ移る

Codex が app-server を Apache-2.0 で出し、DeepSeek が MIT でハーネスを出した。

2027年には、**ハーネスを自社で組む**のが標準的な選択肢になる。

そのとき効くのは、フレームワークではなくランタイムの選定である。

### 2. コンテキストは「積む」から「削る」へ完全に反転する

```text
2025年  CLAUDE.md に全部書け
2026年  system prompt の80%を削っても性能は落ちなかった
        ツール定義がコンテキストの10.5%を食っている
        コンテキスト長が 372k から 272k に縮んだ
```

**削り方の設計が、2027年のコンテキストエンジニアリングになる。**

### 3. 検証とセキュリティが、来年のTOP10に上がってくる

インプレッション12位・13位のトピックが、上位トピックの事故の原因になっている。

```text
2026年  事故は上位トピックの中で語られた
2027年  事故を防ぐ層そのものが話題になる
```

12ヶ月後に同じ集計をしたとき、**この2つが順位を上げていなければ、業界は同じ事故を繰り返す**と思う。

# 調査方法

### 収集

```text
API      : Hacker News Algolia Search API
期間     : 2025-09-03 〜 2026-09-03
条件     : tags=story, points >= 100
検索語   : 156語(製品名・OSS名・概念名・規約名)
取得方式 : フレーズ検索("..." で完全一致)
件数上限 : 100pt 以上に絞ることで、全件取得(打ち切りなし)
```

### 集計

```text
インプレッション = Σポイント + Σコメント数
トピック化       = 検索語を22トピックに束ね、objectID で重複排除
ノイズ除去       = 同名の無関係記事を除外
                  (Temporal=JSの日付API、Droid=F-Droid、
                   Charlie=人名、Cursor Camp=マウスカーソルのゲーム、
                   skills=教育文脈 など)
モデル発表除外   = GPT/Claude/Qwen/GLM/Kimi 等の
                  モデルリリース記事はハーネス対象外として除外
```

### 併用チャネル

| チャネル | 用途 |
|---|---|
| HN Algolia | インプレッションの一次データ(全順位の根拠) |
| WebFetch | 主要記事の原典確認(9本) |
| WebSearch | 原典が取得できなかった事実の裏取り(5件) |

### この調査の限界

1. **英語圏に偏る。** HN は北米中心である。日本語圏・中国語圏での熱量は測れていない
2. **トピック境界は主観。** 特に「OSSコーディングハーネス」と「Harness という概念」の分離、「Claude Code」と「OpenClaw」の重複(規約衝突の記事は両方に属する)は手作業で処理した
3. **100pt 未満を見ていない。** 新興プロジェクトや非英語圏の発表は、この閾値の下に沈んでいる可能性がある
4. **話題量は品質ではない。** 1位が最も優れているという主張ではない。**最も語られた**という主張だけをしている

# 最後に

この集計を始めたとき、私は「Context Engineering」か「Agent Skills」が1位に来ると予想していた。

結果は違った。

**製品が1〜5位を占め、概念は6位以下に沈んだ。**

そして最も皮肉なのは、この記事の主題である「Harness」という概念そのものが**14位**だったことだ。

だが、その12本の中身は、他のどのトピックよりも実用的だった。

学習をせず、編集ツールの形式を変えただけで 6.7% が 68.3% になった実験。

system prompt を80%削っても性能が落ちなかった報告。

25語の制約を1行足しただけで、知性が3%落ちた事故。

**モデルは同じで、変わったのはハーネスだけだ。**

話題の総量は製品に集まる。

しかし性能を決めているのは、順位が低いほうの層である。
